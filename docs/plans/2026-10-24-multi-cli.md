# Multi-CLI Fleet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harness drives a fleet with any of ten agent CLIs — `claude`, `agy`, `codex`, `gemini`, `copilot`, `cursor-agent`, `opencode`, Zcode, `hermes`, `openclaw` — and every Harness feature works for every CLI it lists. A CLI is listed as supported only when its column of the feature × CLI matrix is green; there are no partial claims.

**Architecture:** One adapter file per CLI under `scripts/cli/<cli>.sh`, each implementing the same fixed interface (launch line, pane regexes, done signal, trust, bypass, transcripts, usage, prerequisites). `scripts/cli/dispatch.sh` is the only file that reads `HARNESS_CLI`: it sources the selected adapter, and every caller in `lib.sh`, `supervise.sh`, `usage.sh`, `stats.py`, `init.sh`, `setup.sh`, `start.sh` and `install.sh` calls the interface instead of branching on the CLI name. A CLI without a hook that can hold a turn open gets the Harness-driven goal loop: the drive tick sees the pane go idle, checks the done signal, and re-sends the task bootstrap, which is the contract ralph-loop's Stop hook gives `claude`. Each adapter is proved by `test/test_cli_matrix.sh` against fixtures captured once from the real CLI and checked into `test/fixtures/cli/<cli>/`; the README support table is generated from that matrix's green columns.

**Tech Stack:** Bash 5 (`set -uo pipefail`), `python3` for JSON/TOML/JSONL reads and writes (already a hard dependency of `scripts/lib.sh`), `tmux`, the repo's own test rig (`test/helpers.sh`, `test/run.sh`).

**Spec:** PRD #189 (scope, CLI list, feature rows, acceptance) and #188 (adapter seam, interface, matrix rules). Per-CLI facts, each with its source: `docs/cli-capabilities.md`.

## Global Constraints

- **Task 1 of PRD #189 is this document and `docs/cli-capabilities.md` (#220).** The tasks below are the PRD's remaining children. Task 1 here is #188; nothing else starts before it merges, because every later task adds a file behind its interface.
- **Tasks 2–9 are independent of each other.** Each is blocked only by Task 1, and each is one child issue of #189. They may run in parallel lanes; each touches only its own adapter, fixtures, test file, capabilities section and README row.
- **`HARNESS_CLI` is read in one place.** After Task 1, `grep -n 'HARNESS_CLI' scripts/*.sh` matches only `scripts/cli/dispatch.sh` (PRD #189 acceptance 2). `scripts/cli/*.sh` adapters never read it either: the dispatcher already chose them. A new `if [[ $HARNESS_CLI == … ]]` anywhere else is a review blocker.
- **Facts come from `docs/cli-capabilities.md`, and the doc comes from a source.** An adapter may encode a flag, a path or a TUI string only if its row in the doc cites an official doc page, a source file, or a command run on the host. A row marked `UNVERIFIED` must be confirmed by that CLI's fixture capture, and the doc row updated with the fixture path as its source, in the same PR. Never guess a string from another CLI's TUI.
- **Fixtures are captured from the real CLI, never written by hand.** Each CLI task records, in `test/fixtures/cli/<cli>/`:
  - `VERSION`: the output of `<cli> --version`, the capture date (UTC) and the host;
  - `idle.txt`, `busy.txt`, `limit.txt`, `transient.txt`: `tmux capture-pane -p` of the real TUI in each state (`limit.txt` and `transient.txt` may come from the CLI's own source strings rendered by its test harness when the state cannot be triggered on demand; the fixture's `README.md` says which);
  - `trust.txt` when the CLI has a workspace-trust dialog: the dialog before pre-accept;
  - `transcript.*`: a real transcript or usage sample, trimmed to a few turns, secrets removed;
  - `usage.expected`: the `<model>\t<input>\t<output>\t<cache_read>\t<cache_write>` lines that transcript must fold to;
  - `README.md`: how and when each capture was made.
- **The matrix is the support claim.** `test/test_cli_matrix.sh` runs every feature row for every CLI that has an adapter and prints one `<cli>\t<row>\tok|FAIL|n/a:<reason>` line per cell. `n/a` is allowed only where the PRD's feature cannot exist for that CLI, and its reason is printed in the README support table. A CLI joins the README support table only when no cell is `FAIL`, with "verified on <`VERSION`>, <date>" (PRD #189 acceptance 3).
- **No new dependencies.** Bash + `python3` + `tmux`. Each CLI's own binary is a runtime prerequisite of its fleets only, checked and installed by `cli_prereqs` (Task 1), never by the test suite. The suite runs against fixtures and never needs any agent CLI installed.
- **The task prompt stays out of argv (#213).** Every `cli_launch` line passes only `$HARNESS_BOOTSTRAP_PROMPT`. A CLI that cannot take an initial prompt on its command line gets it by `tmux send-keys` after its idle string appears, never by interpolating `.harness-task.md`.
- **Smoke run, or no claim.** Each CLI task ends with one real fleet session completing a trivial issue end to end, and attaches the log to its PR (PRD #189 acceptance 5). A CLI that cannot be installed or authenticated on the host gets its child labelled `agent-blocked` naming what it needs (account, key, binary), and the README does not list it.
- **Never assert through `bash -c`.** `test/helpers.sh`'s `assert_ok`/`assert_no` run their argv directly, so `lib.sh` and adapter functions are in scope. A `bash -c` child never sourced them and exits 127, which a leading `!` turns into a permanent pass. Where a here-string is needed, pass `grep -qF -- "$x" <<<"$y"` as argv.
- **Every assertion must be one you have seen go red.** Break the adapter function, watch its matrix cell fail, restore it, watch it pass. Report that evidence in the PR.
- **Run the suite with** `bash test/run.sh`; one file with `bash test/test_<name>.sh`. This shell may carry a stale `ENGINE_DIR`/`STATE_DIR`/`HARNESS_HOME` from a live fleet: if tests misbehave, run `env -u ENGINE_DIR -u STATE_DIR -u HARNESS_DIR -u HARNESS_HOME bash test/run.sh`.
- **Commit style:** `feat(cli): …` / `test(cli): …` / `docs: …`, one PR per task, closing that task's child issue.

### The adapter interface

Every `scripts/cli/<cli>.sh` defines all of these. A function that cannot be implemented still exists and returns the documented "unavailable" value, so callers never test for a function's presence.

| function | contract | callers today |
|---|---|---|
| `cli_bin` | the executable (`HARNESS_<CLI>_BIN`, default the binary name) | `start.sh:18`, `setup.sh:9`, `supervise.sh:85` |
| `cli_launch <wd> <uuid> <model> <effort>` | prints the one line `launch_agent` types into the fresh pane: `exec <bin> … "<bootstrap>"`; empty model/effort = the CLI's default | `lib.sh:1460-1465` |
| `cli_lane_settings <wd>` | the per-lane settings `cli_launch` wrote outside the launch line (model, effort, hooks), one `key=value` per line; empty by default. The `launch` stats event records it with the flags | `lib.sh:1466-1468` (`harness_event launch`) |
| `cli_first_input <effort>` | lines `launch_agent` types once `cli_idle_re` first matches, for a CLI that cannot take its prompt or effort on the command line; empty for every other CLI | `lib.sh:1439` (`launch_agent`) |
| `cli_send <sess> <wd> <text>` | delivers a line to the running agent: a nudge, a checkpoint, a driven-loop re-prompt; default `tmux send-keys -l` then `Enter` | `lib.sh:1796-1799`, watchdog nudges, `pause.sh` |
| `cli_kill <sess> <wd>` | ends the session so no turn keeps running; default `tmux kill-session` | every reaper, the watchdog, `supervise.sh` (`sup_checkpoint_and_kill`) |
| `cli_session_id <wd> <uuid>` | the CLI's own session id for this launch: `<uuid>` when the CLI takes a caller-set id, otherwise discovered after launch; empty = not yet known | `stats.py` transcript lookup |
| `cli_idle_re` / `cli_busy_re` / `cli_limit_re` / `cli_limit_menu_re` / `cli_transient_re` | ERE over a `tmux capture-pane -p` capture | `lib.sh:823-872`, `turn.sh:21`, `supervise.sh:62-79` |
| `cli_loop` | `hook` when the CLI's own Stop-like hook re-feeds the task, `driven` when Harness must re-prompt | drive tick |
| `cli_done <wd>` | 0 once the goal loop has ended (promise, max-iter, or error) | `lib.sh:807` (`reap_finished_inject`), reapers |
| `cli_trust <dir>` / `cli_trusted <dir>` | pre-accepts the workspace-trust gate for `<dir>` (no-op when the CLI has none) / reads that back, so the matrix can check the write without knowing the file format | `lib.sh:229` (`ensure_trusted`) |
| `cli_bypass <dir>` / `cli_bypassed <dir>` | makes the main session AND its sub-agents run without approval prompts / reads that back | `lib.sh:256` (`ensure_bypass`) |
| `cli_skill <name>` | how a prompt invokes a skill on this CLI (`/handoff` on `claude`); used by the checkpoint text | `lib.sh:1796-1799` |
| `cli_transcripts <wd> <session-id>` | transcript paths for stats, one per line; empty = unavailable | `stats.py` |
| `cli_usage <transcript>…` | `<model>\t<input>\t<output>\t<cache_read>\t<cache_write>` per model | `stats.py` (#185) |
| `cli_limit_usage` | `<account>\t<window>\t<pct>\t<resets_at>` lines; rc 1 = unavailable | `usage.sh:55` (#194) |
| `cli_prereqs [--install]` | checks (and with `--install`, installs) the binary, its plugins/skills/hooks; prints one line per missing piece | `install.sh` (`ensure_skills`), `setup.sh` (installs, then fails if anything is still missing, #253) |
| `cli_runnable` | 0 iff the installed binary actually runs; default `<bin> --version` | `install.sh` (`check_prereqs`) |
| `cli_uninstall` | removes what Harness installed into the CLI itself (agy: the `harness-ralph` plugin); default nothing | `uninstall.sh` |
| `cli_turn_secs <pane>` | seconds the running turn has taken, from the CLI's turn timer; `0` = no turn; empty = the CLI draws no timer (then `turn.sh` reads a running turn off `cli_busy_re`, and `HARNESS_TURN_MAX` cannot apply) | `turn.sh` (`turn_secs`, #207) |
| `cli_interrupted_re` | ERE: the line a turn interrupted by Escape prints; empty = none (then the interrupt has landed once the pane is no longer busy) | `turn.sh` (`turn_interrupt`) |
| `cli_bg_re` | ERE: footer timers/counters that move while work runs; default elapsed-time shapes | `supervise.sh` (`sup_watch_pane`) |
| `cli_pane_prompt_line <pane>` / `cli_prompt_text <line>` | helpers over `cli_idle_re`: the LAST prompt line's number (a CLI that echoes submitted prompts at the prompt's column leaves earlier matches in scrollback), and the text typed after the prompt | `turn.sh`, `supervise.sh` |

A lane's own model and effort come from its worktree: the worktree hook writes `model=<m>` / `effort=<e>` lines to `<wt>/.harness-lane`, and `launch_agent` passes them as `cli_launch`'s `<model>` / `<effort>` for every CLI (#253).

Create `test/test_cli_matrix.sh`:

```bash
#!/usr/bin/env bash
# test_cli_matrix.sh — PRD #189 / #188: every feature row for every CLI that has an adapter, run
# against fixtures captured from the real CLI (test/fixtures/cli/<cli>/). One cell per row; a CLI's
# README support row is generated from its column. --tsv prints the cells instead of asserting.
set -uo pipefail
HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$HERE/../scripts/lib.sh"
source "$HERE/helpers.sh"
make_env
FIX="$HERE/fixtures/cli"
UUID=11111111-2222-3333-4444-555555555555
TSV=0; [[ "${1:-}" == --tsv ]] && TSV=1
cell(){ local cli="$1" row="$2"; shift 2
  if (( TSV )); then if "$@" >/dev/null 2>&1; then printf '%s\t%s\tok\n' "$cli" "$row"; else printf '%s\t%s\tFAIL\n' "$cli" "$row"; fi
  else assert_ok "$cli: $row" "$@"; fi; }
pane(){ cat "$FIX/$1/$2.txt"; }
has(){ grep -qF -- "$1" <<<"$2"; }
no_task_text(){ ! grep -qF UNIQUE_TASK_MARKER <<<"$1"; }
re_hits(){ grep -qE -- "$1" <<<"$2"; }

for cli in $(cli_list); do
  ( cli_load "$cli"; F="$FIX/$cli"; WD="$RUN_DIR/$cli-wd"; mkdir -p "$WD"
    printf 'GOAL: UNIQUE_TASK_MARKER\n' > "$WD/.harness-task.md"
    cell "$cli" fixtures-recorded test -s "$F/VERSION"
    line="$(cli_launch "$WD" "$UUID" "$(sed -n 1p "$F/model")" high)"
    cell "$cli" launch-bootstrap-prompt has "$HARNESS_BOOTSTRAP_PROMPT" "$line$(cli_first_input high)"
    cell "$cli" launch-no-task-text no_task_text "$line"
    cell "$cli" launch-model has "$(sed -n 1p "$F/model")" "$line$(cli_lane_settings "$WD")"
    cell "$cli" session-id test -n "$(cli_session_id "$WD" "$UUID")"
    cell "$cli" idle-is-idle re_hits "$(cli_idle_re)" "$(pane "$cli" idle)"
    cell "$cli" busy-is-busy re_hits "$(cli_busy_re)" "$(pane "$cli" busy)"
    [[ -f "$F/trust.txt" ]] && cell "$cli" trust-dialog-is-not-idle eval '! re_hits "$(cli_idle_re)" "$(pane "$cli" trust)"'
    cell "$cli" idle-is-not-busy eval '! re_hits "$(cli_busy_re)" "$(pane "$cli" idle)"'
    cell "$cli" transient-stalls session_stalled "$(pane "$cli" transient)"
    cell "$cli" busy-never-stalls eval '! session_stalled "$(pane "$cli" busy)"'
    cell "$cli" limit-parks session_limit_idle "$(pane "$cli" limit)"
    cell "$cli" limit-is-not-transient eval '! session_stalled "$(pane "$cli" limit)" || session_limit_idle "$(pane "$cli" limit)"'
    cli_trust "$WD"; cell "$cli" trust-pre-accepted cli_trusted "$WD"
    cli_bypass "$WD"; cell "$cli" bypass-covers-subagents cli_bypassed "$WD"
    cell "$cli" done-signal-before eval '! cli_done "$WD"'
    cell "$cli" usage-from-transcript test "$(cli_usage "$F"/transcript.* | sort)" == "$(sort "$F/usage.expected")"
    cell "$cli" prereqs-named test -n "$(cli_prereqs 2>&1)"
    cell "$cli" checkpoint-skill test -n "$(cli_skill handoff)"
    cell "$cli" loop-mode re_hits '^(hook|driven)$' "$(cli_loop)"
    cell "$cli" send-and-kill-defined eval 'declare -F cli_send && declare -F cli_kill' 
    (( TSV )) || finish ) || rc=1
done
exit "${rc:-0}"
```

Each fixture dir also carries `model`: one model id the CLI accepts, from its `docs/cli-capabilities.md` row. The default `cli_send`, `cli_kill` and `cli_first_input` live in `dispatch.sh`; an adapter overrides only what its CLI needs.

# dispatch.sh — the ONE reader of HARNESS_CLI (PRD #189 acceptance 2). Sourced by lib.sh; loads the
# selected adapter, whose functions every caller uses instead of branching on the CLI name.
CLI_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
cli_list(){ local f; for f in "$CLI_DIR"/*.sh; do f="${f##*/}"; [[ $f == dispatch.sh ]] || echo "${f%.sh}"; done; }

## What this plan deliberately leaves undone

- **rtdd's agent instructions for these CLIs.** rtdd writing its skill or instruction file for each CLI is the sibling PRD in VocanicZ/rtdd (PRD #189 non-goals). Each adapter's `cli_prereqs` installs whatever rtdd already ships for its CLI (`rtdd skill prompt` into the CLI's skill dir, as `lib.sh` does for `agy` today) and warns, never fails, when rtdd has nothing for it.
- **New Harness features.** Only the PRD's feature rows are in scope. A CLI capability Harness does not use today (OpenCode's HTTP server, Codex's `exec --json` event stream, Gemini's pane-title state) is recorded in `docs/cli-capabilities.md` but not adopted, even where it would make scraping a pane unnecessary. `openclaw` (Task 9) is driven headless only because its TUI cannot work in a worktree. Moving any other CLI off pane-scraping is a later PRD.
- **Mixed-CLI fleets.** One fleet drives one `HARNESS_CLI`. Per-lane CLI choice (a `codex` reviewer on a `claude` fleet) needs the dispatcher to load several adapters at once under distinct names; it is not planned.
- **Usage windows for CLIs that do not expose them.** `cli_limit_usage` returns "unavailable" wherever the capabilities doc's usage row is `MISSING`; those fleets checkpoint on the limit message only, as `agy` does today (`usage.sh:50-52`). No CLI's account API is scraped.
- **Keeping fixtures current.** A fixture pins the CLI version it was captured from. Re-capturing on every upstream release is not automated; the README row's "verified on <version>" says how old the claim is, and a CLI whose TUI changes breaks its matrix column on the next capture, not silently.
- **A ZCode build or account.** Its identity is confirmed (`docs/cli-capabilities.md` § `zcode`), but it ships no prebuilt CLI and needs a Z.ai account. If Task 7 cannot build or authenticate it on the host, that child is labelled `agent-blocked` naming what is missing and the README does not list `zcode` (PRD #189).
- **Windows and macOS hosts.** Every capture and smoke run is on the Linux fleet host. Path differences elsewhere (`%APPDATA%` config dirs) are not handled.
